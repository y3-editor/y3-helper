## Why

目前离线重建会沿用原 GMP 的表格、存档配置、场景装饰、资源对象和纹理。磁盘上的这些数据发生变化时，用户仍需要为此打开编辑器保存。目标是让现有 Y3 Helper 入口把这些已落盘的变更用于本地测试，并给出可核验的生成结果。

## What Changes

- 继续通过侧边栏重建命令和 MCP `generate_gmp` 更新现有多关卡 GMP；两个入口均处理全部有效关卡，MCP 保留 `dryRun`。生成过程无需启动游戏、编辑器或连接游戏服务器。
- 支持七个目标段：表格 `table_data`、玩家存档配置 `archive_data`、全局存档配置 `global_archive_data`、场景装饰 `dec_data`、资源对象 `resource_object_data`、地表纹理 `texture_data`、纹理植被 `texture_foliage_data`。表格只读取编辑器保存的 JSON，非 JSON 文件不参与离线重建。存档以本地运行时能读到新配置为验收，覆盖项目级数据优先于关卡副本的情况。
- 新增支持的段与原段语义一致时复用原编码字节；内容变化时，对照同版本编辑器对同一份输入生成的包验证。缺少可选源与合法清空明确区分；目标段第一次出现或清空后应省略时，按同版本编辑器验证过的规则添加或移除该段；损坏或不支持的有效输入会报告关卡、段和路径，并保留该关卡原包。
- `cloud_res_dep_data` 和 `resource_data` 原样保留。触发器、`custom_eca`、`custom_api` 等既有保留项也不扩展。范围限于有基础 GMP 的本地工程，不负责从零制包、重算资源依赖、正式发布打包或修改玩家实际存档。

## Capabilities

### Modified Capabilities

- `gmp-generate`: 扩展离线重建范围，增加新段的内容与类型验收，定义存档配置在项目级和关卡级的处理边界。

## Impact

复用现有多关卡生成、段解析和原子写入流程，保持首次备份和 `onSave` 隔离。更新侧边栏说明、MCP 描述和生成报告。以 `F:\DM28\local_release` 的 28 张关卡为回归基线；另准备原生 JSON 表格及非空全局存档的小型样本，分别覆盖真实项目里缺失的情况。
