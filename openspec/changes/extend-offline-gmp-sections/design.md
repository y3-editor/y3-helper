## Context

只读检查 `F:\DM28\local_release`：装饰和资源对象解码后各 28/28 关与本地文件一致；纹理植被 28/28，地表纹理 27/28，差异关卡为 `Cave`。主关卡的 3 张 JSON 全局表可复现原 GMP 的解密内容，28 个关卡包的表格内容相同，但关卡源文件存在差异。样本的玩家存档在项目和关卡目录有不同副本，28 个包均未检出旧版全局存档段；需要非空样本验证全局配置的实际加载路径。

## Decisions

- **一个生成入口，按段转换。** 复用既有生成结果和写入流程。所有目标段先完成构建与校验，再写该关卡；存在成组的项目级必需产物时，先完成整组的构建校验，并明确提交和失败恢复规则。外部用户无需另外安装 Python 或访问编辑器源码。已有编辑器逻辑用于生成对照样本，不在扩展中启动编辑器。
- **纹理与场景装饰。** 纹理文件按 zlib 二进制读取，按原载荷比较后再用 Zstd 封装。装饰和资源对象读 `.data` 的结构化数据，用只接受数据类型的解码器：不会导入类、执行构造器或调用 pickle 中的函数；核对整数、元组、二进制、层级以及旧版 JSON 是否需要兼容。用格式正确的空数据验证“清空”行为。
- **表格。** 开启主关卡共享时，从入口关卡读取关卡表；关闭时从各自关卡读取。`archive/init_tables` 是工程级输入，要遵循编辑器的命名和合并规则。只读取编辑器落盘的 `.json`，覆盖数据表、全局表、多级主键、空值、默认值与同名冲突；其他文件不读取、不参与重建。按包内加密元数据选择正确的打包流程；不能识别时不写错格式。保留字符串键、整数键和向量等类型。
- **存档配置先确认运行时契约。** 现代 2.0 项目以项目级 `archive/archive.json`（玩家）与 `archive/mapscore.json`（全局）为候选权威源，关卡副本只用于已证实需要的兼容路径。用非空全局配置和玩家槽位样本验证本地启动到底读项目文件、既有 GMP 段，还是其他构建产物；验证已有项目级源是否直接生效。已确认：若本地运行时直接读取项目配置，且同版本编辑器不写入该 GMP 段，实际读取到新配置即满足验收；生成报告说明配置由项目读取，无需重建该段。仅当同版本编辑器的对照包与本地加载共同证明有必要时，才为特定存档段列出明确的允许新增条件，或记录并实现必要的项目级派生产物。旧 GMP 和项目源同时存在时，按验证后的优先级处理；生成过程不回写用户编辑的源配置。 `1120test` 三源分歧的实际启动结果确认该 2.0/2.5D 版本 73 模式的默认值仍来自关卡 GMP：以项目 JSON 为构建输入，不回退关卡副本；更新已有 95，非空全局配置可新增 110，显式空字典时省略 110。
- **段存在性。** 编辑器可省略空段。对照首建和清空样本，列出七个目标段中可以按编辑器规则新增或移除的段及适用工程模式，覆盖第一次添加表格与全局存档。`1120test` 实存对照已确认：2.0 / 2.5D、GMP 头版本 73、基础包 `desc.encrypt_sections` 声明 `table_data` 加密时，首次非空 JSON 表格新增旧段 96，按 `SectionProp` 顺序写入。同模式用户实存样本已确认：有效数据表只剩合法表头、且无任何可导出表时省略 96；缺失 JSON 源、非 JSON 文件、坏表头均不等同于明确清空。不推广到其他包格式。其余段沿用现有的仅替换规则；已找到有效非空源但不支持写入时，应说明限制，不报告该段已更新。
- **比较规则与失败行为。** 按段比较实际逻辑数据：区分字符串/数值键、列表/元组、二进制，并保留有效的顺序规则。内容未变时直接复用原段；内容变化时，以解码后与编辑器一致为标准。资源清单和其余保留段不参与重建，保持原字节。缺少可选输入时保留原段并报告；合法空数据按编辑器语义应用；应当存在的输入丢失、解析失败或不支持时明确报错。`dryRun` 执行相同构建校验，只报告会发生的变更。

## Verification

每个任务从磁盘输入到 `generate_gmp` 结果和读回 GMP 做一条完整验证。使用小型对照样本覆盖非默认格式、两种共享设置与存档加载路径，再在 `F:\DM28\local_release` 上跑 28 关 `dryRun`、散列核对和工程副本实写。只改一个源时，新增范围内仅预期段及应受共享影响的关卡发生变化；恢复旧内容或连续生成两次后，验证内容不变的段没有重编码。用手动本地启动确认游戏读取新表值和新存档配置；需要编辑器保存或启动游戏的操作由用户执行，离线生成及自动化检查独立运行。
